# Project: Pebble Android APK builds for Obtainium

## Goal
Automatically build a release APK of `coredevices/mobileapp` and publish it as a GitHub Release so any Obtainium user can install it by pointing at the fork.

## Repository
- Upstream: https://github.com/coredevices/mobileapp
- Fork (builds): `https://github.com/GoofyAF/mobileapp`
- Obtainium source type: GitHub Releases
- Obtainium source URL: `https://github.com/GoofyAF/mobileapp`
- Package name: `coredevices.coreapp`

## CI Pipeline (`.github/workflows/nightly-release.yml`)

| Trigger | Behavior |
|---------|----------|
| Push to `master` | Builds APK and creates a `nightly-N` release |
| Daily at 06:00 UTC | Merges upstream, builds, creates release |
| `workflow_dispatch` | Manual trigger with same result |

The merge step pulls from `upstream/master` so the build always includes the latest upstream changes without manual syncing.

## How APK signing works

`LOCAL_RELEASE_BUILD=true` in `local.properties` tells AGP to sign the release APK with the debug keystore (`.android/debug.keystore`). This is fine for Obtainium — there is no real release keystore. The CI runner has a debug keystore pre-generated by the Android SDK tools.

The flag is read in `androidApp/build.gradle.kts` (line ~16); when set, the `release` build type signs with the debug config instead of the unset `keystore.jks` release config.

## Where the APK comes from

The Android application module is **`androidApp`** (`applicationId = coredevices.coreapp`, `androidApp/build.gradle.kts:56`). `composeApp` is a Kotlin Multiplatform *library* and does not produce an APK. All build/release paths below therefore target `androidApp`.

- dummy Firebase config: `androidApp/src/google-services-dummy.json`
- APK output: `androidApp/build/outputs/apk/release/`
- Crashlytics mapping upload task (skipped): `:androidApp:uploadCrashlyticsMappingFileRelease`

## Build prerequisites (CI — Ubuntu)

All satisfied by `actions/setup-java@v4` + stock Ubuntu runner:
- JDK 17 (Temurin)
- Android SDK (comes with `setup-android` or AGP downloads what it needs)
- No Nix, no patchelf, no aapt2 override needed on Ubuntu

## Build prerequisites (local — NixOS)

If you ever need to build locally on NixOS, the critical steps are:
1. `nix-shell shell.nix` (provides JDK 17, Gradle, Android SDK 36, NDK 29)
2. Override aapt2: `-Pandroid.aapt2FromMavenOverride=$ANDROID_HOME/build-tools/36.0.0/aapt2`
3. Exclude Crashlytics upload: `-x :androidApp:uploadCrashlyticsMappingFileRelease`
4. Set `LOCAL_RELEASE_BUILD=true` in `local.properties`
5. Copy `androidApp/src/google-services-dummy.json` → `androidApp/src/google-services.json`

The `build-apk.sh` script in the repo root encapsulates all of this.

## Modified files (carried from earlier NixOS work)

| File | Change | Why |
|------|--------|-----|
| `cactus/build.gradle.kts` | `ndkVersion = "29.0.14206865"`, cmake `version = "3.31.6"` | NixOS provides specific NDK/CMake versions; Gradle won't auto-download them. CI on Ubuntu also benefits from pinning. |
| `cactus/src/{android,common,ios}Main/.../Cactus.kt`, `cactus.def` | NDK/native interop adjustments | Pins the native cactus module to the pinned NDK/CMake toolchain. |
| `gradle.properties` | `android.ndkVersion=29.0.14206865`, `kotlin.native.ignoreDisabledTargets=true` | Optional on Ubuntu CI (NDK already pinned in `cactus/build.gradle.kts`). Kept in `pebble2` (Forgejo) history; not present in this fork's `master` yet. |

These changes are compatible with both NixOS local builds and Ubuntu CI builds.

## What happens on first fork

1. Fork `coredevices/mobileapp` on GitHub
2. Clone the fork locally
3. Copy the workflow file and these build modifications into the fork
4. Enable Actions in the fork repo settings
5. Push — the workflow should fire and create the first nightly release
6. Add the fork URL to Obtainium

## Known issues / gotchas

- **Crashlytics upload**: Excluded via `-x :androidApp:uploadCrashlyticsMappingFileRelease` because the Firebase project tokens aren't configured. The mapping file is not uploaded, but the APK is fully functional.
- **AAPT2 on NixOS local builds**: The AGP-downloaded aapt2 binary is incompatible with NixOS's glibc stub. The SDK-bundled aapt2 (from Nix) works fine; pass via `-Pandroid.aapt2FromMavenOverride`. Not an issue on Ubuntu CI.
- **Upstream merge conflicts**: If `git merge upstream/master` fails, the CI job stops. The user must manually resolve conflicts in their fork and push.
- **NDK / CMake version drift**: If upstream changes the pinned NDK or CMake version, the `cactus/build.gradle.kts` overrides may conflict. Keep an eye on CI failures after upstream merges.
